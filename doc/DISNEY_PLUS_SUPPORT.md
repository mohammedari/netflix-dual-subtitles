# Disney+対応

## 目的と範囲

この文書は、バージョン1.1.0で追加したDisney+対応の調査結果、実装境界、セキュリティ要件、テスト方法をまとめる。全体設計は`DESIGN.md`を参照し、本書ではDisney+アダプター固有の内容だけを扱う。

対象はWindows版の最新Google Chromeと`https://www.disneyplus.com/`の動画再生ページである。Netflixと同様に非公開のプレイヤー動作へ依存するため、Disney+側の変更によって動作しなくなる可能性がある。

## 2026年8月19日の実機調査

ログイン済みDisney+タブで、Hive/BAMGrid系プレイヤーがHLSを使用していることを確認した。字幕の配信経路は次のとおりだった。

1. 再生ページがDisney+の再生APIからHLSマスターURLを取得する。
2. HLSマスターの`#EXT-X-MEDIA:TYPE=SUBTITLES`行に言語、表示名、強制字幕属性、字幕メディアプレイリストURIが含まれる。
3. 字幕メディアプレイリストが複数のWebVTT断片を列挙する。
4. WebVTT断片には、ローカル字幕時刻をメディア時刻へ写像する`X-TIMESTAMP-MAP`が含まれ得る。

調査時に字幕プレイリストとWebVTTが`media.dssott.com`配下からHTTPSで配信されることを確認した。実アカウントのコンテンツID、署名付きURL、トークン、プレイリスト本文、字幕本文はリポジトリへ保存していない。

## 実装構成

### MAIN worldブリッジ

`src/page/disney-bridge.js`はDisney+ページだけへ`document_start`で注入される。`fetch`と`XMLHttpRequest`でページ自身が取得したHLSレスポンスを観測し、字幕トラックだけを正規化して`window.postMessage`へ渡す。

ページ読み込み後に拡張が応答を取り逃した場合に備え、Resource Timingで観測済みのHLS URLを最大40件まで再確認する。URLやレスポンス本文はログへ出さず、拡張ストレージにも保存しない。

ブリッジはChrome拡張APIを使用しない。Disney+は再生期間によって`video.currentTime`が作品全体の時刻と一致しないため、シーク要求はプレイヤーが標準対応する`ArrowLeft` / `ArrowRight`へ変換する。これによりDisney+自身の10秒シークと境界処理を使用する。

Disney+の標準字幕は閉じたShadow DOM内の`.dss-hls-subtitle-overlay`へ描画される。ブリッジは`document_start`で`Element.prototype.attachShadow`をラップして生成されたShadowRootをメモリ内に保持し、コンテンツスクリプトからの`NATIVE_CAPTIONS`要求に応じて字幕レイヤー専用styleを挿入する。拡張OFF、ページ離脱、エラー時はstyle本文を空にして標準字幕を復元する。映像やプレイヤー操作UIにはスタイルを適用しない。

### 字幕取得

`src/background/service-worker.js`はDisney+字幕メディアプレイリストを取得し、非コメント行にあるHTTPSの`.vtt`断片だけを解決する。取得先は`media.dssott.com`に限定し、認証情報を送信しない。

防御上の上限は次のとおりである。

- 字幕本文の合計: 5,000,000文字
- 1プレイリストのWebVTT断片: 500件
- 並列取得: 最大6件

取得した断片はメモリ上で結合してコンテンツスクリプトへ返し、永続化しない。

### WebVTT時刻補正

`src/shared/core.js`は、結合された各`WEBVTT`文書を個別に解析する。`X-TIMESTAMP-MAP`に`LOCAL`と`MPEGTS`がある場合、次のオフセットを各キューへ加える。

```text
offsetMs = MPEGTS / 90 - LOCAL(ms)
```

同じ開始時刻、終了時刻、本文を持つキューは重複排除する。未知の字幕形式や空のプレイリストは推測せずエラーとして扱う。

Disney+ではMedia Sourceの期間切替により、表示中`video`のローカル時刻と作品全体の表示時刻にオフセットが生じる場合がある。コンテンツスクリプトはプレイヤーの`.text-to-speech-status`が通知するミリ秒値からオフセットを更新し、字幕描画とキャプチャの時刻へ適用する。Netflixでは従来どおり`video.currentTime`を直接使用する。

## トラック選択

言語コードは小文字のBCP 47形式へ寄せ、`jpn`と`eng`もそれぞれ`ja`と`en`へ正規化する。共通選択ロジックは次の優先順位を使用する。

1. `ja`または`en`の完全一致
2. `ja-JP`、`en-US`などの地域バリアント
3. 通常字幕
4. 強制字幕
5. SDH / CC

対象言語が提供されていない場合、翻訳や別言語の代用は行わず「利用不可」と表示する。

## メッセージと権限の境界

- ページからのメッセージは`event.source`、`event.origin`、内部source値、type、payload形状を検証する。
- コンテンツスクリプトはトラック数、文字列長、HTTPS URLを再検証する。
- サービスワーカーは送信元タブがNetflixまたはDisney+であることを確認する。
- 字幕取得はNetflix CDNまたは`media.dssott.com`だけを許可する。
- DRM、Widevine、暗号化された映像セグメント、ライセンス通信には触れない。

## テスト

自動テストには、実サービス由来の識別子と署名を除去したHLSフィクスチャを使用する。

- HLSマスターから字幕だけを抽出すること
- 許可外ホストを拒否すること
- Disney+シークが10秒単位かつ境界内であること
- HLS字幕断片URLを安全に解決すること
- `X-TIMESTAMP-MAP`をメディア時刻へ変換すること
- 完全一致、通常字幕、強制字幕、SDHの優先順位
- manifestの権限と参照ファイル

実サービスでは`MANUAL_TESTS.md`に従い、少なくとも日英字幕表示、10秒シーク、再生切替、通常画面と全画面のキャプチャ、SPA遷移、標準字幕復元を確認する。

## 既知の制約と保守

- Disney+がHLSの属性名、字幕形式、CDNホスト、プレイヤーDOMを変更すると追従が必要になる。
- Resource Timingからの再取得は、CORSまたはブラウザのタイミング情報制限により失敗する場合がある。通常は`document_start`の通信観測が主経路となる。
- 長編作品で500件を超えるWebVTT断片が使われた場合は安全上エラーになる。上限を変更する場合は総容量と同時接続数も再評価する。
- ネイティブ字幕のDOMセレクターは非公開実装に依存する。重複表示または復元失敗は実機で回帰確認する。
- DRM環境ではPNGの映像部分が黒くなる場合がある。検出は警告専用で、保存自体は止めない。

障害調査時も署名付きURLや字幕本文をログへ追加しない。必要なフィクスチャはホスト、パス、識別子、トークン、本文を完全にサニタイズしてからコミットする。

## バージョン1.1.0の実機確認結果

2026年8月19日、Windows版ChromeのDisney+長編作品で次を確認した。

- 日本語・英語トラックがともに`ready`になる
- 再生中と一時停止中に日本語・英語が同時表示される
- 閉じたShadow DOM内のDisney+標準字幕が重複表示されない
- `J` / `L`がDisney+標準の10秒シークへ伝達される
- `K`で再生と一時停止が切り替わる
- 再生中の`C`でPNGが保存され、保存後に再生状態が復元される
- 画面キャプチャに映像と拡張の日英字幕が含まれる
- ページコンソールに拡張由来のエラーがない

この確認では、全画面キャプチャ、字幕が片方だけの作品、Disney+内SPA遷移、エピソード切替、長時間連続再生、ポップアップでのOFF→ONによる標準字幕復元は実施していない。Netflix側の実サービス回帰も未実施であり、リリース前には`MANUAL_TESTS.md`の残項目を確認する。
